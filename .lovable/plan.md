## Part 1 — Comprehensive Learner Progress Report PDF

A new "Download Progress Report" action for learners (and a tutor-facing version that highlights areas of concern).

### What goes in the report

1. **Cover** — learner name, curriculum/grade, date range, target grade, exam dates.
2. **Executive summary** — XP, streak, total study minutes, tasks completed, mock exams taken, average score, overall mastery %.
3. **Charts** (rendered as PNG via `chart.js` + `chartjs-node`-style canvas in browser, then embedded in jsPDF):
   - Mastery per subject (horizontal bar)
   - Score trajectory across mock exams (line)
   - Study minutes per day, last 30 days (bar)
   - Topic accuracy heat strip (strongest → weakest)
4. **Per-subject breakdown** — mastery %, topics covered, weak topics, recent quiz accuracy.
5. **Exam mode results** — each mock exam: subject, date, score %, time taken, marks breakdown, AI feedback summary.
6. **Tasks completed** — totals by type (micro-revision, active recall, exam questions, flashcards) + completion rate.
7. **AI Improvement Plan** — generated by a new edge function `generate-progress-plan`:
   - Top 3 weak concepts with root cause
   - 7-day action plan (concrete daily tasks)
   - Recommended Study Mode focus areas
   - Suggested past-paper questions
8. **For Tutor section** (only included when "Generate for tutor" is selected):
   - "Areas of concern to start with" — ranked list with suggested teaching approach (reuses logic from `generate-student-insights`)
   - Recommended session structure for the first 3 sessions

### Implementation pieces

- **New file** `src/lib/generateProgressReport.ts` — jsPDF + jspdf-autotable builder. Charts rendered to offscreen `<canvas>` with `chart.js` (already a common lib; will add `chart.js`).
- **New file** `src/lib/chartToImage.ts` — renders a chart config to a data URL for PDF embed.
- **New hook** `src/hooks/useProgressReport.ts` — aggregates data from: `study_attempts`, `mock_exam_results`, `daily_tasks`, `subject_mastery`, `user_progress`, `bookings`, plus calls the new edge function for the AI plan.
- **New edge function** `supabase/functions/generate-progress-plan` — takes the aggregated metrics + weak topics, returns the structured improvement plan JSON (uses Lovable AI Gateway, same pattern as `generate-student-insights`).
- **New component** `src/components/ProgressReportButton.tsx` — dropdown: "Download for me" / "Download for tutor".
- **Wire-in points**:
   - Learner: `LearnerProfileTab` (new "Progress Report" row) and `LearnerActivityTab` header.
   - Tutor: `StudentInsightsPanel` gets a "Download full report" button that produces the tutor-flavoured PDF for the selected student.

## Part 2 — Bounce-rate fix on the landing page

Current landing (`/`) loads hero immediately, then lazy-loads everything below in a single Suspense boundary. Likely bounce drivers from inspecting `HeroSection.tsx` and `Index.tsx`:

1. **Hero copy is generic** — "Learn smarter. Pass faster." with no proof, no specific outcome, no urgency.
2. **Two equal-weight CTAs** ("Start Learning" + "Find a Tutor") — choice paralysis. No primary action.
3. **No social proof above the fold** — testimonials and stats live far below.
4. **Hero image is a generic stock-style group photo** — doesn't show the product.
5. **No price anchor or free-trial signal above the fold** — visitors don't know the cost/risk.
6. **Mobile (current 552px viewport)** — checklist 2-col grid + two stacked full-width CTAs push the second CTA below the fold. The image loads above the CTAs on mobile, delaying the action.
7. **Footer/cookie/PWA prompts** all in one Suspense — large JS chunk delays interaction; cookie banner can also cover the CTA on first paint.
8. **No analytics segmentation** — `analytics.pageView('home')` is a stub (logger only), so we have no real bounce data per source.

### Proposed changes

**A. Above-the-fold rewrite (HeroSection)**
- Replace tagline with outcome-led copy + proof: e.g. "Pass your ZIMSEC / IGCSE exams with a personal AI tutor + verified human tutors. 7-day free trial, R0 to start."
- Single primary CTA "Start free trial" (yellow). Secondary becomes a low-weight text link "I'm a tutor →".
- Add a thin social-proof strip directly under the headline: star rating + "Trusted by 1,200+ students" (use real number from DB if available, otherwise pull from `StatsSection`).
- Mobile: reorder so CTA appears immediately under headline; image becomes a smaller round inset, not full-width.
- Add a real product screenshot (Study Mode dashboard) instead of the stock photo on desktop, in a phone-frame.

**B. First-paint performance**
- Preload the hero image with `<link rel="preload" as="image">` in `index.html`.
- Split the giant Suspense — keep `AppShowcase` + `HowItWorksSection` in a first lazy boundary (so they're visible on first scroll), defer `StudyModeSection`/`StatsSection`/`Testimonial`/`Trust`/`Footer` to a second lazy boundary triggered by `IntersectionObserver`.
- Defer `PWAInstallPrompt` and `CookieConsent` until after first user interaction (idle callback) so they don't block the CTA visually.

**C. Trust + risk reduction band**
- Insert a slim band right under the hero (before AppShowcase) showing: "★ 4.8 rating · 30-min money-back · Verified tutors · Powered by AI". This is the highest-leverage anti-bounce block.

**D. Real analytics**
- Replace the no-op `analytics.pageView` with a minimal Plausible-style event ping (or simply log to a new `landing_events` table) so we can measure bounce per CTA in future. Out of scope to add a full analytics provider, but we'll capture: page view, CTA click, scroll-depth 50%, scroll-depth 90%.
- Add a new `landing_events` table (`session_id`, `event`, `path`, `created_at`, anonymous) with insert-only RLS for the anon role.

### What I will NOT change without confirmation
- Brand colours, logo, overall design language (locked per memory).
- The auth/tutor flows behind the CTAs.
